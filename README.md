# elhaitam.com

Personal portfolio and engineering blog for Haitam Elgharras — software engineer in Morocco working with Java, Spring Boot, React, TypeScript, Docker and Kafka.

**Live:** [www.elhaitam.com](https://www.elhaitam.com)

## Stack

React 18 and TypeScript on Vite, with React Router v7 in framework mode. Every route is prerendered to static HTML at build time (`ssr: false` plus `prerender`), so the site is served as static files and hydrates into a SPA. Styling is plain CSS with an HSL token system — no component library, no CSS-in-JS.

Blog posts are authored in Notion and pulled in during the build.

## Requirements

Node 24.x (see `.nvmrc`). The content script relies on Node 24's native TypeScript stripping, so earlier versions will not run it.

## Getting started

```bash
git clone git@github.com:Haitam-Elgharras/myPortfolio.git
cd myPortfolio
npm install
npm run dev
```

Then open <http://localhost:5173>.

Blog content is not committed, so `/blog` is empty on a fresh clone until you run `npm run content` with Notion credentials. Everything else works without any setup.

## Scripts

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server on port 5173 |
| `npm run build` | Pulls blog content, type-checks, then builds and prerenders into `build/client/` |
| `npm run content` | Syncs blog posts from Notion into `src/content/` and regenerates the feeds and sitemap |
| `npm run lint` | ESLint over `ts`/`tsx`, warnings fail the run |
| `npm run typecheck` | Route typegen plus `tsc` |
| `npm run typecheck:scripts` | Type-checks `scripts/`, which the main build does not cover |
| `npm run preview` | Vite preview |

To inspect the prerendered output, serve `build/client/` statically **without** an SPA rewrite — otherwise every deep link is served the homepage HTML and hydrates against the wrong markup.

## Layout

```
src/
  components/   grouped by feature, plus shared/ for cross-cutting pieces
  pages/        one file per route
  data/         site content as typed arrays
  content/      blog posts, generated by npm run content (gitignored)
  lib/          blog helpers and SEO meta builder
  hooks/        useIsDarkTheme, useMounted, useRouteScroll, useScrollReveal
  three/        lazy-loaded WebGL background
scripts/        build-time only: Notion sync, markdown pipeline, feeds, sitemap
```

Site content lives in `src/data/*.ts` rather than in JSX — edit `portfolioData.ts` to change projects.

## Blog

Posts live in a Notion database. `npm run build` runs `npm run content` first, so a deploy re-fetches from Notion; publishing is therefore just triggering a deploy.

Set `NOTION_TOKEN` and `NOTION_BLOG_DATABASE_ID` (see `.env.example`) locally and in the Vercel project. Without them the build fails on Vercel by design, rather than shipping an empty blog; locally the sync is skipped with a warning so the site still builds.

A GitHub Actions workflow pings a Vercel deploy hook every six hours as a fallback for posts published and forgotten.

## Deployment

Vercel, zero configuration, via `vercelPreset()` in `react-router.config.ts`. Do not add `vercel.json` rewrites — they conflict with the preset.
